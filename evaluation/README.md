# GreenTrust Module 1 — Quantitative Evaluation

Evaluates ONLY the ACTUAL OUTPUT produced by the existing Module 1 processor. Does NOT re-process documents to create results, does NOT modify Module 1, the frontend, backend, authentication, MongoDB, or the `/process/document` API.

**Flow:** Document → Existing Module 1 → Actual Output → Evaluation → Metrics

---

## What It Measures (6 Metrics)

| # | Metric | Description |
|---|---|---|
| 1 | **Processing Success Rate** | Successful documents / total × 100 |
| 2 | **Text Extraction Accuracy** | Token-level P/R/F1 against verified `expected_text` when available. Reports N/A if no verified text exists. |
| 3 | **Structured Information Extraction** | P/R/F1 for dates, measurements, financials, key\_data, relevant\_terms (and overall) using TP/FP/FN |
| 4 | **Structured JSON Correctness** | Checks whether expected VALUES are correctly placed in the corresponding JSON fields — NOT just field existence |
| 5 | **SHA-256 Integrity / Change Detection** | Compares Module 1's hash with independently computed hash. Flips one byte and verifies hash changes. Called integrity/change detection, NOT authenticity. |
| 6 | **Processing Performance** | Actual Module 1 execution time: average, min, max, median, and per-type (PDF/DOCX/Image-OCR) |

## Quick Start

### Step 1: Place documents

Put 10–20 real documents in the subfolders:

```
evaluation/test_documents/pdf/      ← PDF files
evaluation/test_documents/docx/     ← DOCX files
evaluation/test_documents/images/   ← PNG / JPG files
```

### Step 2: Install evaluation dependencies

```bash
cd evaluation
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

You also need Tesseract OCR installed on your system:

- **macOS:** `brew install tesseract`
- **Ubuntu/Debian:** `sudo apt-get install tesseract-ocr`
- **Windows:** Download from https://github.com/UB-Mannheim/tesseract/wiki

### Step 3: Start the existing FastAPI processor

In a separate terminal:

```bash
cd processor
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
```

The processor must be running at `http://localhost:8000`.

### Step 4: Generate ground truth candidates

```bash
cd evaluation
source venv/bin/activate

# Interactive review (recommended — shows detected values, accept/edit/skip each)
python build_ground_truth.py

# Or auto-accept candidates without review
python build_ground_truth.py --auto-accept
```

**IMPORTANT:** This tool reads the ORIGINAL document files directly using PyMuPDF, python-docx, and Tesseract OCR. It NEVER calls Module 1's `/process/document` endpoint. The detected values are CANDIDATES — you should review and correct `ground_truth.json` against the original documents before running evaluation.

The candidate generator detects:
- Dates
- Measurements with units
- Financial values with currencies
- Key-value fields
- Hotel/property name
- Relevant sustainability terms
- Optional `expected_text` (capped at 5000 chars)

### Step 5: Run evaluation

```bash
python evaluate.py
```

This sends each document through the EXISTING Module 1 processor (`POST /process/document`), captures the ACTUAL returned output, and compares it against ground truth to calculate all 6 metrics.

Options:

```bash
python evaluate.py --processor-url http://localhost:8000
python evaluate.py --ground-truth ground_truth.json
python evaluate.py --timeout 120
```

### Step 6: View results

After evaluation completes:

- **`evaluation/results.json`** — Full machine-readable results (all 6 metrics + per-document breakdown)
- **`evaluation/evaluation_report.txt`** — Human-readable summary report
- A concise summary is also printed to the terminal

## How Evaluation Works

`evaluate.py` measures what Module 1 ACTUALLY produced:

1. Checks that the processor is online (`GET /health`)
2. Loads `ground_truth.json` (verified by you in Step 4)
3. For each test document:
   - Sends it to `POST /process/document` (the existing endpoint)
   - Measures processing time with `time.perf_counter()`
   - Captures the ACTUAL returned: `extracted_text`, `structured_data`, `sha256`, `metadata`, `extraction_method`
   - Compares actual output vs ground truth
   - Independently computes SHA-256 and compares with processor's hash
   - Flips one byte of the file and verifies the hash changes
   - If `expected_text` exists in ground truth, computes token-level text P/R/F1; otherwise reports N/A
4. Aggregates all 6 metrics across documents
5. Writes `results.json` and `evaluation_report.txt`

**The evaluator does NOT re-process documents to create results.** It only sends documents through Module 1 and measures what Module 1 actually returned.

---

## How Ground Truth Is Built

`build_ground_truth.py` is a **candidate generator + verification tool**. It:

1. Reads the ORIGINAL document files (NOT through Module 1)
2. Independently extracts text using PyMuPDF (PDF), python-docx (DOCX), Tesseract (images + scanned PDFs)
3. Runs regex-based detection for dates, measurements, financials, key-value pairs
4. Saves candidates to `ground_truth.json`
5. You review and correct the candidates against the original documents

**Ground truth represents information actually present in the ORIGINAL documents.** It is NEVER created from Module 1 output.

---

## Normalization

Harmless differences are normalized before comparison:

- Case (uppercase vs lowercase)
- Whitespace (extra spaces, line breaks)
- Number formatting (1,250 vs 1250)
- Currency (₹ / Rs / INR all treated as INR)
- Unit formatting (m³ vs m3, liters vs litres vs L)

---

## Metrics Formulas

**Precision** = TP / (TP + FP)

**Recall** = TP / (TP + FN)

**F1** = 2 × Precision × Recall / (Precision + Recall)

**Success Rate** = successful documents / total documents × 100

**JSON Correctness** = correctly placed expected values / total expected values × 100

**Integrity Accuracy** = 100% if (original hash matches AND modified hash changes), else 0%

---

## Important Notes

- **No fake results.** All metrics come from actual Module 1 execution.
- **No production code changes.** The evaluation module only reads files and sends HTTP requests to the existing processor.
- **Expected text is optional.** Text accuracy reports N/A when no `expected_text` is present in ground truth.
- **SHA-256 is integrity/change detection**, NOT authenticity verification.
- **Metric 4 checks value placement**, not just whether JSON fields exist. It verifies that expected ground-truth values are actually present in the corresponding `structured_data` fields.
