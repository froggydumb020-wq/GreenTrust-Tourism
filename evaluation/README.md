# GreenTrust Module 1 — Quantitative Evaluation

Evaluates the existing GreenTrust Module 1 (Data Ingestion & Preprocessing) using automated ground truth generation and quantitative metrics.

**This module is completely independent of production code.** It does not modify the frontend, backend, FastAPI processor, MongoDB, authentication, or the `/process/document` API. It only *sends* documents to the running processor and *compares* the output.

---

## What It Measures

| Metric | Description |
|---|---|
| **Processing Success Rate** | Documents successfully processed / total documents × 100 |
| **Structured Extraction P/R/F1** | Precision, Recall, F1 for dates, measurements, financials, key\_data, relevant\_terms (and overall) |
| **JSON Field Accuracy** | Percentage of expected response fields present and non-empty |
| **SHA-256 Integrity** | Independently computed hash vs processor hash, plus change detection (flip one byte → hash must change) |
| **Processing Time** | Average, min, max, median, and per-type (PDF / DOCX / Image-OCR) |
| **Text Evaluation (optional)** | Token-level P/R/F1 if `expected_text` is present in ground truth |

## Quick Start

### Step 1: Place documents

Put 10–20 real documents in the subfolders:

```
evaluation/test_documents/pdf/      ← PDF files
evaluation/test_documents/docx/     ← DOCX files
evaluation/test_documents/images/   ← PNG / JPG files
```

### Step 2: Install evaluation dependencies

```bash
cd evaluation
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

You also need Tesseract OCR installed on your system:

- **macOS:** `brew install tesseract`
- **Ubuntu/Debian:** `sudo apt-get install tesseract-ocr`
- **Windows:** Download from https://github.com/UB-Mannheim/tesseract/wiki

### Step 3: Start the existing FastAPI processor

In a separate terminal:

```bash
cd processor
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
```

The processor must be running at `http://localhost:8000`.

### Step 4: Build ground truth

```bash
cd evaluation
source venv/bin/activate

# Interactive review (shows detected values, accept/edit/skip each)
python build_ground_truth.py

# Or auto-accept everything without review
python build_ground_truth.py --auto-accept
```

This independently extracts text from each document (using PyMuPDF, python-docx, and Tesseract — the same libraries but called separately, NOT through the processor) and detects:

- Dates
- Measurements with units
- Financial values with currencies
- Key-value fields
- Hotel/property name
- Relevant sustainability terms

The result is saved to `ground_truth.json`. You can review and manually edit it before running evaluation.

### Step 5: Run evaluation

```bash
python evaluate.py
```

This sends each document to the processor, captures the response, compares against ground truth, and calculates all metrics.

Options:

```bash
python evaluate.py --processor-url http://localhost:8000
python evaluate.py --ground-truth ground_truth.json
python evaluate.py --timeout 120
```

### Step 6: View results

After evaluation completes:

- **`evaluation/results.json`** — Full machine-readable results (all metrics + per-document breakdown)
- **`evaluation/evaluation_report.txt`** — Human-readable summary report
- A concise summary is also printed to the terminal

## How Ground Truth Is Built

`build_ground_truth.py` does **not** call the GreenTrust processor. It independently:

1. Discovers PDF, DOCX, PNG, JPG files in `test_documents/`
2. Extracts text using PyMuPDF (PDF), python-docx (DOCX), or Tesseract (images + scanned PDFs)
3. Cleans and normalizes the text
4. Runs regex-based detection for dates, measurements, financials, key-value pairs
5. Detects hotel/property names from key-value fields and text patterns
6. Finds sustainability-relevant terms
7. Saves everything to `ground_truth.json`

You can review detected values interactively or use `--auto-accept` to skip review.

---

## How Evaluation Works

`evaluate.py`:

1. Checks that the processor is online (`GET /health`)
2. Loads `ground_truth.json`
3. For each test document:
   - Sends it to `POST /process/document` (the existing endpoint)
   - Measures processing time with `time.perf_counter()`
   - Captures `extracted_text`, `structured_data`, `sha256`, `metadata`, `extraction_method`
   - Compares structured output vs ground truth using normalized set operations
   - Independently computes SHA-256 and compares with processor's hash
   - Flips one byte of the file and verifies the hash changes
   - If `expected_text` exists in ground truth, computes token-level text P/R/F1
4. Aggregates all metrics across documents
5. Writes `results.json` and `evaluation_report.txt`

### Normalization

Harmless differences are normalized before comparison:

- Case (uppercase vs lowercase)
- Whitespace (extra spaces, line breaks)
- Number formatting (1,250 vs 1250)
- Currency (₹ / Rs / INR all treated as INR)
- Unit formatting (m³ vs m3, liters vs litres vs L)

## Metrics Formulas

**Precision** = TP / (TP + FP)

**Recall** = TP / (TP + FN)

**F1** = 2 × Precision × Recall / (Precision + Recall)

**JSON Field Accuracy** = correct fields / total expected fields × 100

**Success Rate** = successful documents / total documents × 100

**Integrity Accuracy** = 100% if (original hash matches AND modified hash changes), else 0%

---

## Important Notes

- **No fake results.** All metrics come from actual processor execution.
- **No production code changes.** The evaluation module only reads files and sends HTTP requests.
- **Expected text is optional.** You do not need to manually transcribe documents. Text evaluation is only computed if you include `expected_text` in `ground_truth.json`.
- **SHA-256 is integrity/change detection**, not authenticity verification.
